# Nice Idea - 立项索引

`nice_idea/` 用于沉淀可以在 InterviewQA 基础上继续孵化的实验性项目。这里的 Idea 不以堆叠功能为目标，而是强调明确的问题定义、可验证的技术机制和可逐步落地的工程方案。

## Idea 列表

### 1. [面试数字孪生](interview-digital-twin/001-面试数字孪生.md)

建立概念级个人能力模型，而不是只记录题目是否做过。系统综合正确率、信心值、反应时间、提示次数和遗忘速度，持续估计掌握度与不确定性，并通过信息增益选择下一道最值得回答的问题。

核心方向：

- 题目到细粒度概念的知识图谱；
- FSRS、BKT、IRT 和主动学习的分层组合；
- 能力估计、信心校准和遗忘建模；
- “明天面试最可能挂在哪里”的证据化风险预测；
- 基于 Event Sourcing 的模型回放与版本比较。

### 2. [对抗式多 Agent 面试场](adversarial-multi-agent-interview/001-对抗式多-Agent-面试场.md)

由面试官、质疑者、领域专家、表达教练和裁判承担不同职责，通过角色隔离、独立评估、对抗追问和显式裁决模拟真实技术面试。

核心方向：

- 显式状态机约束多 Agent 编排；
- 基于 Claim Graph 的主张抽取、矛盾检测与证据追踪；
- 多评委盲评、置信度校准和分歧保留；
- 面试事件回放、模型重放和 Agent 级评测；
- 根据任务动态启用 Agent，平衡质量、延迟和成本。

## 两个 Idea 的关系

两者可以独立建设，也可以组成完整闭环：

```text
面试数字孪生
根据能力缺口和信息增益选择问题
        ↓
对抗式多 Agent 面试场
提问、追问、评估并生成结构化证据
        ↓
面试数字孪生
更新概念掌握度、风险和下一题策略
```

- 数字孪生负责“问什么”和“能力如何变化”；
- 多 Agent 面试场负责“怎么问”“如何追问”和“如何评估”；
- 二者共享题目 Rubric、概念图谱、观测事件和模型版本信息；
- 组合后形成“诊断 → 面试 → 评估 → 更新画像 → 自适应选题”的学习闭环。
