# 多智能体的记忆如何管理，怎样避免爆掉？

## 题目

多智能体的记忆你是怎么管理的？不会爆掉吗？

## 面试直接答

多 Agent 记忆是否膨胀取决于通信拓扑和上下文重放方式，不能一概说指数增长。若 N 个 Agent 每轮各产生 K Token、运行 T 轮，单看新增内容是 O(NKT)；如果每个 Agent 每轮都重发完整共享历史，累计输入可能接近二次增长；全量广播和分支复制还会进一步放大。

我会把权威任务状态、近期工作上下文、完整轨迹和长期记忆分层。目标、约束、计划、完成证据和副作用状态用结构化存储；近期必要消息进入上下文；大日志和原始轨迹外置；长期记忆只接收稳定、验证且可复用的信息。摘要和被检索回来的记忆仍占 Token，外置不等于免费。

控制膨胀需要按语义边界滑窗、结构化摘要、去重、按需检索和子任务隔离，同时保留原文指针并定期从权威记录重建摘要。压缩是否值得要算一次压缩成本与未来复用轮数，不能预设固定压缩比。并发更新使用版本和原子切换，避免 Agent 读到新旧混合状态。

## 详细解析

### 一、增长模型

设每轮新增 c Token。单个会话第 t 轮携带完整历史时，单轮输入 O(ct)，累计 T 轮约 O(cT²)。N 个 Agent 如果各自重放同一历史，近似再乘 N；若只传递增量或摘要，则接近 O(NcT)。实际还受缓存、路由和拓扑影响。

### 二、四层存储

| 层 | 内容 | 处理 |
|---|---|---|
| 权威状态 | 目标、约束、计划、副作用 | 结构化、版本化、不可由摘要覆盖 |
| 工作上下文 | 当前步骤必要证据 | 语义滑窗和选择性保留 |
| 轨迹归档 | 完整消息、工具输出 | 外置、可回放、按权限读取 |
| 长期记忆 | 稳定可复用知识 | 准入、验证、过期和冲突管理 |

### 三、摘要风险

增量摘要会累积误差，尤其容易丢失否定、数字和未决事项。摘要必须带源指针，并定期从原始轨迹重建。用户消息或工具结果不因来源类型就自动高优先级，还要看与任务的关系、验证状态和时效。

### 四、去重与复杂度

逐条与全部历史计算 embedding 会形成 O(n²) 开销。应先用规范化哈希做精确去重，再按时间窗口或 ANN 索引做语义候选。合并结果必须真正写入输出，且来源 Agent 数要按唯一 agent_id 统计，不能用消息条数代替。

### 五、并发与成本

异步压缩完成后通过版本号或原子指针切换新摘要；下一轮绑定明确版本。成本计算为“本次压缩输入输出费用 - 后续每轮节省 × 预计复用次数”，首次压缩通常增加成本，只有后续复用足够多才回本。

### 六、框架边界

AutoGen、CrewAI 等内置记忆和回调会随版本变化，示例应标明版本和伪代码属性。框架提供压缩钩子不代表自动解决正确性、并发和长期污染。

### 七、按通信拓扑建模

集中式协调只需主 Agent 接收子任务摘要；点对点结构按订阅关系传递；全广播最简单但复制最重。应统计每轮每个接收者实际看到的 Token，而不是只统计新生成消息。分支合并还可能重复携带共同前缀，需要内容寻址或引用减少复制。

### 八、写入准入与生命周期

并非所有轨迹都进入长期记忆。候选内容经过去重、来源检查、任务结果验证、敏感信息过滤和复用价值判断后再晋升。长期条目要有作用域、版本、有效期、权限和删除传播；一次任务中的临时猜测应随任务结束归档或淘汰。

### 九、摘要重建协议

摘要候选生成后校验目标、约束、数字、未决项、副作用和源指针，使用版本号原子发布。每隔一定变化量或关键阶段从原始轨迹重建，而不是永远在旧摘要上继续摘要。重建频率依据误差和成本测量，不使用固定轮数。

### 十、检索预算

检索先按权限、任务、角色、版本和时间过滤，再做关键词/向量召回和重排。为每类内容分配 Token 预算，优先任务契约与当前状态，再放证据与历史经验。被召回的内容仍占上下文，因此“向量库存了多少”与“单轮能读多少”是两个问题。

### 十一、去重的正确实现

先用规范化哈希消除完全重复，再用 ANN 找有限语义候选，避免新消息与全部历史两两计算。合并后生成新的规范化内容并保留所有来源 ID；消息数量、唯一 Agent 数和独立证据数分别统计，不能混用。

### 十二、容量与质量指标

监控每任务上下文 Token、累计重放 Token、摘要成本、检索命中、回查原文、陈旧读取、冲突、长期记忆增长和删除延迟。容量下降但约束丢失、错误经验传播或回查频繁，说明压缩不合格。

### 十三、降级与恢复

压缩器或向量服务故障时，回退到最近已验证摘要和结构化状态，必要时减少并发或暂停新任务，不能用空上下文继续。异步压缩只在完整版本生成并验证后切换，读者始终绑定明确版本，避免新旧内容混合。

### 十四、容量推演示例

10 个 Agent 每轮各产生 500 Token、运行 100 轮，新增内容是 50 万 Token。如果每个 Agent 每轮都读取此前全部团队历史，累计输入不是 50 万，而会随历史长度叠加到更高数量级。若改为主协调者维护结构化状态、子 Agent 只收局部任务并返回 200 Token 证据摘要，主上下文增长与广播成本都会显著下降。

这个估算仍只是模型，真实系统还要加入固定提示、缓存命中、检索返回、分支失败和摘要调用，最终以调用日志计量。

### 十五、压缩盈亏示例

一次摘要花费相当于 20k 输入和 1k 输出，之后每轮减少 8k 输入；若任务只剩一轮，可能不回本，若还剩二十轮则有明显收益。但若摘要丢失约束导致一次昂贵重跑，节省会被抵消，所以成本公式必须包含质量风险。
