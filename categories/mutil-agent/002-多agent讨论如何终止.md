# 多个智能体讨论起来没完没了，怎么让它停下来？

## 题目

多个 Agent 讨论无法自然终止时，如何设计可靠的停止条件？

## 面试直接答

多 Agent 不会自动知道什么时候该停，根因不是“模型天生爱说话”，而是控制器持续调用、任务没有外显完成条件、Agent 没有终止动作，或奖励只鼓励继续提出内容。因此终止必须是运行时协议，而不是一句“达成共识后停止”。

首先把目标转成可验证的完成条件、必须覆盖的问题和允许保留的分歧。每轮记录新证据、状态变化、未解决项和动作重复度；满足客观验收时成功结束，连续无进展时结束为停滞，预算耗尽时暂停并交付当前结论。开放问题允许“未达成共识”作为合法结果。

共识、语义相似度、投票和自报置信度只能作为辅助信号，因为多个 Agent 可能共享同一个错误。仲裁 Agent 也只是概率模型，不能替代测试、环境状态或人工决策。系统始终需要轮数、时间、Token 和费用硬上限，避免任何软条件失效后无限运行。

## 详细解析

### 一、终止状态

- SUCCEEDED：客观验收条件满足。
- NO_CONSENSUS：关键分歧已清晰记录，继续讨论收益不足。
- STALLED：连续多轮无新证据或状态变化。
- PAUSED_BUDGET：达到预算，可恢复。
- NEEDS_HUMAN：涉及价值判断、授权或高风险决策。
- FAILED：关键依赖不可恢复失败。

### 二、信号优先级

第一层是测试、环境状态和业务规则；第二层是覆盖率、未解决项和新证据；第三层才是共识度、相似度和模型置信度。结构化 JSON 便于解析，但不会让内容自动变真。

### 三、停止协议

每轮由控制器更新 unresolved_items、evidence_added、state_delta 和 action_fingerprint。若验收通过则成功；若硬预算触发则保存检查点；若连续 k 轮没有新证据或状态变化则停滞。k 和其他阈值由任务历史数据校准，不存在通用 3 轮或 0.85。

### 四、仲裁边界

仲裁者适合汇总论点、检查覆盖和明确分歧，不应凭更高置信度宣布事实。可验证争议交给工具和数据，价值冲突交给授权人。对开放研究题，输出分歧树和下一步证据需求比强行共识更诚实。

### 五、框架注意事项

AutoGen、CrewAI 等终止 API 会随版本变化，文档应记录版本并把示例标为伪代码。无论框架如何封装，外层都必须保留独立预算和可恢复停止状态。

### 六、先定义讨论产物

讨论可以产出唯一答案、候选排序、风险清单、分歧树或下一步实验。不同产物有不同终止条件：代码修复可由测试验收，架构选型可在硬约束满足且权衡明确时结束，价值判断则可能必须交给授权人。

把“达成共识”作为所有任务的目标，会迫使本来合理的多方案问题产生虚假一致。高质量终止允许保留少数意见、证据缺口和需要外部决策的变量。

### 七、控制器状态机

控制器每轮更新当前主张、支持/反对证据、未解决项、动作指纹、预算和产物覆盖。状态可以在 `RUNNING`、`VERIFYING`、`SUCCEEDED`、`NO_CONSENSUS`、`STALLED`、`PAUSED_BUDGET`、`NEEDS_HUMAN` 间迁移。终止由控制器执行，Agent 只能提出终止建议。

硬上限始终独立存在。触发时先保存当前产物和恢复点，而不是丢弃讨论。若外部验证正在运行，可以等到安全检查点或记录为未完成，不能把缺失结果写成反对证据。

### 八、进展的可操作定义

新发言只有在增加可验证证据、消除一个未决项、提出可检验反例、改善候选方案或改变决策边界时才算进展。换一种说法重复观点不算。语义相似度能检测明显重复，但对数字、否定和细微条件不可靠。

### 九、仲裁协议

仲裁者先检查覆盖和证据，再把争议分成事实、预测、偏好和授权。事实争议交给工具或数据；预测比较假设与实验；偏好展示取舍；授权问题请求负责人。仲裁者不应用一个综合置信度把这些类别混成单一答案。

### 十、预算分配与防串谋

可以先给各角色独立提出意见的阶段，再开放交叉质询，减少第一位发言形成锚定。预算按未解决项和风险分配，而不是每个 Agent 固定同样轮数。多个同源 Agent 可能相关失败，增加人数不能替代多样证据。

### 十一、验证终止策略

离线比较任务完成率、无共识识别正确率、平均轮数、Token、误停和过度讨论。对抗样本包括多数人一致但事实错误、开放问题无唯一答案、验证工具暂时失败和同一观点反复改写。终止更早只有在产物质量和安全不退化时才算改进。

### 十二、案例：多数共识仍然错误

三个 Agent 都根据同一份过期 API 文档判断参数合法，投票得到 3:0。控制器调用真实 schema 校验后失败，应把争议归类为事实验证失败并更新证据，而不是因为共识度高而停止。共享证据导致的相关错误不会被增加投票人数消除。

### 十三、案例：开放架构题如何停止

团队讨论消息队列选型时不存在唯一真值。任务契约要求覆盖吞吐、顺序、一致性、运维、成本和迁移；当两个候选都满足硬约束、差异已量化，而剩余选择依赖业务风险偏好时，可以以 `NEEDS_HUMAN` 交付决策表。强行继续直到所有 Agent 选同一个，既浪费预算又掩盖真实取舍。

### 十四、终止器自身的故障

终止器可能误把合法迭代判为重复，也可能在软信号永不满足时漏停。因此硬预算必须位于独立控制层，终止决策也要记录触发信号和状态快照，便于离线复盘误停与漏停。
