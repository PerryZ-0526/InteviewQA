# Hermes 的自进化机制

## 题目

详细解释一下 Hermes 的“自进化”机制。

## 标签

## 面试直接答

这里要先区分 Hermes Agent 的一般学习能力和 NousResearch 公开的 Hermes Agent Self-Evolution 项目。按 2026 年 8 月的公开仓库，后者使用 DSPy 与 GEPA 做反思式进化搜索：读取当前技能和执行轨迹，生成或加载评测数据，提出多个文本变体，在任务集上评估，通过测试、大小、缓存兼容性和语义保持等约束门，再把最佳候选以 PR 方式交给人工审查。

它不是“在线收集每个用户反馈后自动修改生产系统”。当前公开状态中，技能文件优化已实现；工具描述、系统提示、工具实现代码和持续自动循环仍在后续阶段。公开护栏明确要求人工 PR 审查、不能直接提交生产，因此自进化更准确地说是“受评测和版本控制约束的离线候选搜索”。

效果是否提升取决于评测集是否代表真实任务。若数据污染、奖励指标有漏洞或反复在同一评测集上搜索，系统可能过拟合或奖励投机。所以必须保留独立测试集、版本化候选、回滚和人工判断，也要允许搜索结果是“没有可接受改进”。

## 详细解析

> 公开状态核验日期：2026-08-10。

### 一、当前公开闭环

当前技能/提示 → 评测数据与执行轨迹 → GEPA 生成候选 → 候选运行评测 → 约束门 → Pareto/指标选择 → PR → 人工审查。

GEPA 会利用轨迹分析失败原因并提出定向变体，但这仍是基于代理指标的搜索，不等于获得真实因果解释。

### 二、已实现与路线图

| 阶段 | 目标 | 公开状态 |
|---|---|---|
| Phase 1 | Skill 文件 | 已实现 |
| Phase 2 | 工具描述 | 计划中 |
| Phase 3 | 系统提示片段 | 计划中 |
| Phase 4 | 工具实现代码 | 计划中 |
| Phase 5 | 持续改进流水线 | 计划中 |

因此不能把后四阶段描述成已经上线的生产能力。

### 三、数据与隐私

可记录的是用户允许保存的输入输出、工具轨迹、环境结果和可公开决策摘要，不应默认收集或暴露原始思维链。使用真实会话历史时要脱敏、最小化、隔离权限并遵守保留策略。

### 四、评测设计

条件失败率必须同时有成功和失败样本作分母；只分析失败集合无法计算 P(失败|特征)。评测集应覆盖主路径、边界和严重低频风险，并保留不参与优化的独立测试集。第二个模型复核不是独立事实验证，关键结果仍要靠测试和环境状态。

### 五、发布护栏

所有候选版本化，完整测试通过后才进入人工 PR；不得自动直发生产。灰度比例和观察时间由业务流量、影响和统计功效决定，不使用固定 5% 或 2 小时。低频但高损的安全事件应更保守，而不是因为“长尾”就更激进。

### 六、参考

- 官方仓库：https://github.com/NousResearch/hermes-agent-self-evolution
- Hermes Agent 文档：https://hermes-agent.nousresearch.com/docs/

### 七、候选搜索到底在优化什么

自进化对象是可版本化文本资产，例如技能说明；优化器根据执行轨迹和评分反馈提出候选，再在同一评测协议下比较。候选变化可能同时影响工具选择、步骤数量、输出格式和失败恢复，因此不能只看单个平均分。

Pareto 选择的意义是保留不同取舍：某候选成功率更高但 Token 更多，另一候选更短但边界失败略多，二者可能都不是绝对支配。最终是否接受还取决于风险、维护性和业务预算。

### 八、约束门为什么独立于奖励

如果只优化任务得分，搜索可能通过删除安全说明、写死评测答案或扩大工具权限取得“提升”。因此大小限制、语义保持、缓存兼容、格式、权限和安全测试应作为不可被平均分抵消的硬门槛。

约束门也要版本化并有反例测试。技能变短不一定更好，变长也不一定更完整；重点是关键行为是否保持、失败边界是否明确、调用方是否仍能稳定解析。

### 九、评测污染与过拟合

开发集用于提出和筛选候选，验证集用于调参，隐藏测试集只用于最终估计。反复查看隐藏集分数并据此修改，实际上已经把它变成开发集。还应按任务类型、难度、语言和工具切片，防止平均提升来自简单样本而关键长尾退化。

真实轨迹会受到模型版本、工具环境和数据变化影响。复现实验时固定这些变量或记录版本，多次运行并报告方差。没有统计或业务意义的微小提升应允许判定为“无改进”。

### 十、从轨迹到反馈的边界

轨迹可以显示在哪一步失败、调用了什么工具和环境返回什么，但模型对失败原因的文字反思只是假设。可靠流程用对照实验验证假设：只改变候选技能，保持样本和环境一致，观察失败类型是否按预期改善。

不得默认收集用户秘密、完整会话或私有代码。数据进入优化管道前需得到授权、脱敏、设定保留期与访问控制；PR 中也不能泄露原始敏感轨迹。

### 十一、发布、回滚与持续监控

候选通过离线门禁后进入人工审查，合并时记录来源评测、差异和风险。生产灰度要监控成功率、最差切片、成本、延迟、人工接管和安全事件，并设置明确回滚条件。

技能、工具和系统提示会相互作用。只回滚其中一个资产可能无法恢复旧行为，因此发布清单要记录完整配置组合。持续监控发现分布漂移后，应更新评测数据再开启新一轮离线搜索，而不是让生产流量直接改写当前版本。

### 十二、面试追问

**这是不是强化学习？** 它同样利用评价信号做搜索，但公开流程更接近对文本候选的反思式进化与评测选择，不能直接等同于对模型参数做在线 RL。

**为什么必须人工 PR？** 自动评分不覆盖全部安全、语义和组织约束；版本控制与责任审批提供可审计的最终边界。

### 十三、奖励投机示例

若评测只检查是否输出指定字段，候选技能可能学会始终填默认值而获得高格式分，却降低事实正确性；若只测短任务，候选可能删除长任务恢复说明来缩短 Token。应把格式、任务结果、边界样本和安全不变量分层验证，并检查候选差异是否存在绕过评测的捷径。

### 十四、与人工调优的关系

自动搜索擅长并行生成和筛选候选，人工擅长判断评测是否代表真实目标、变化是否可维护及风险是否可接受。自进化不是替代维护者，而是把“提出候选—运行评测—形成差异”自动化，让人工把精力放在目标、证据和发布责任上。
