# 项目概览

> ai顾问助手、ai销售
>
> **counselor** → /ˈkaʊnsələr/ **copilot** → /ˈkoʊpaɪlət/

### 一句话定位

这是**瑞思教育（英语培训机构）的 AI 销售辅助系统**：给销售顾问生成外呼/上门的策略建议、通话后产出报告、给客户打画像标签，外加周复盘、金句话术库、质量评分等一整套闭环。后端是 FastAPI + MySQL + 阿里 DashScope（通义系 LLM），重活全部异步化。

### 核心架构模式：请求 → 异步任务

这是理解全项目的钥匙。所有重活（策略、报告、复盘、金句挖掘、评测）都是 fire-and-forget：

1. API 路由收请求 → 写一行 `algo_task`（status=pending）→ 立刻返回 task\_id；
2. `TaskScheduler`（`src/tasks/task_scheduler.py`）每 5 秒轮询数据库认领任务，分发给对应 handler；
3. handler（`src/handlers/`，按 task\_type 分派）跑算法、写结果表；
4. `TaskCallbackClient` 往 `TASK_CALLBACK_URL` 发完成通知（3 次指数退避重试）；
5. 调用方轮询 `GET /algo/*/tasks/{task_id}` 拿结果。

### 分层结构
```
api/routes/      → 路由层（薄，转发给 service）
services/         → 业务编排层
crud/             → SQLAlchemy CRUD 封装
db/models/        → ORM 模型（无外键关系，join 全靠显式查询）
handlers/         → 后台任务执行体（调度器驱动）
ai_service/algo/  → 移植的算法核心（profile_v3 / profile_tags / strategy / quality）
strategy_generation/ + consensus_knowledge/ → 策略共识 Agent（call 场景主路径）
review_generation/ → 周复盘生成
core/config.py    → 全局唯一 Settings 单例
```

其中 `ai_service/algo/adapter.py` 是唯一同时懂 ORM 和算法内部的桥接文件；纯算法层不允许碰 DB。

### 六大业务模块

**1. 策略生成（主产品）**。三个 API 场景（首拨/跟进外呼、上门访谈）映射到 call/visit 两个算法场景。call 场景的默认主路径是**策略共识 Agent**（`strategy_generation/`，v2）：一个 agent 顺序调用 6 个 RAG 工具，在 21 张共识知识卡 + 金句库里检索、校验草稿，产出接地的话术策略；金句检索以 Milvus `golden_quotes_v2` 为主读，不可用才回退 DB。整条链有安全/接地/PII 门禁，trace 落 `strategy_result.source_stats_json`。

**2. 外呼报告 + 画像标签**。报告任务先过三道 ASR 有效性闸门（短音频 &lt;20s、空转写 ≤20 有效字符、ASR 异常过滤器识别的机器播报/首语挂），无效通话不产报告、不污染画像。画像标签是四层链：L0 业务字段 → L1 规则 → L2 LLM → L3 模型（XGBoost 或 LLM flash，一个开关切换），高层产出不被低层覆盖，路由是代码里的硬编码常量而非 DB 驱动。标签缓存在 `entity_tag` 表，报告跑完能喂给后续策略请求。

**3. 质量评分**。对每通电话打 6 因子 + 5 红线，融合历史逐通状态（置信度加权 + 30 天半衰），最终 Q 分。目前在线打分是灰度（报告成功后另起 `factor_score` 后续任务），只对管理后台可见。

**4. 金句闭环**。从 Δ（通话前后质量分变化）挖掘金句 → 沉淀 Milvus 向量库 → 策略生成时召回复用，形成自增强。2026-08 刚修复打通全链路，并有双库对照评测背书（Milvus 显著胜出）。

**5. 周复盘（个人 + 团队）**。4×qwen3.8-max 主流程 + 周期指标环比 + 优秀/遗憾案例卡。有一套销售状态「拉模型」：算法侧主动去 CRM 拉客户状态变更流水（带 TTL 水位记账），用于案例筛选、邀约耗时测算等；老的数据侧推送接口保留为兜底。

**6. 评测与发布自动化 + 提示词自优化**。金标集生产（分层抽样 → 3LLM 投票 → Validator → 人工审核）→ 冻结数据集 → 夜间自动 eval → release gate → 人工 promote。提示词已全量 DB 化（43 个 key 走 PromptRegistry，血缘落 `prompt_trace_json`），自优化闭环是 dream → propose → evaluate → **人工 accept 才激活**，没有任何自动激活路径。还有 3LLM 周巡检（复盘、外呼报告标签）持续往 badcase 池里灌 triage 燃料。

### 必须知道的关键坑

- **import 路径**：跑脚本要 `PYTHONPATH=src`；
- **每一处 LLM/embedding 调用必须走闸门**（`run_with_gate_async`），否则 `llm_call_metric.namespace` 会落 `unknown`；
- **新增 LLM 提示词必须注册到 PromptRegistry** 并落 prompt\_trace\_json，禁止裸提示词常量；
- `audio_url` 混存三种形态（直链/裸 objectKey/过期签名 URL），统一走 `audio_source_service.resolve_audio_url` 分流，换签有前缀白名单；
- 无效通话（`call_type=无效`）只进指标计数、不进任何分析环节；
- 403 `Workspace.AccessDenied` 是百炼的瞬时鉴权抖动，按可重试处理。
