# 11

当前成熟产品的共同选择：默认让 Agent 使用语义稳定、结果受限的工具；需要自由度时提供受约束的遍历或搜索 DSL；只有 CodeGraphContext 这类偏开发者图工具箱的产品，才把只读 Cypher直接作为普通 MCP Tool 暴露。

---

ground-truth-kg 不应该走两个极端：
```
极端一：只有几个僵化 Tool
极端二：直接把 Neo4j/Cypher 完全暴露给所有 Agent
```

推荐形态：


| Profile    | 暴露能力                  | 使用者                         |
| ---------- | --------------------- | --------------------------- |
| `core`     | 5 个领域 Tool            | MARK、Codex、Claude Code 默认使用 |
| `graph`    | core + 结构化 `kg_query` | 复杂跨仓库分析                     |
| `advanced` | graph + 只读 Cypher     | KG 开发人员、受信任调试任务             |



| Tool                         | Profile  | 核心作用                |
| ---------------------------- | -------- | ------------------- |
| `kg_get_status`              | core     | 检查 KG 可用性和当前数据版本    |
| `kg_resolve_entities`        | core     | 把自然语言、仓库名等解析为标准实体   |
| `kg_get_context`             | core     | 获取某个实体的完整 Agent 上下文 |
| `kg_traverse_graph`          | core     | 从实体出发进行受限图遍历        |
| `kg_get_evidence`            | core     | 获取事实对应的原始证据         |
| `kg_query`                   | graph    | 使用结构化 DSL 组合复杂查询    |
| `kg_execute_readonly_cypher` | advanced | 执行受限的只读 Cypher      |




## 1. `kg_get_status`

### Tool 描述

> 获取 Ground Truth KG 当前服务状态、活动数据版本、图规模、数据覆盖率和可用能力。Agent 在首次使用 KG 或怀疑数据异常时应优先调用。

### Agent 何时使用

- 一次任务中第一次访问 KG。
- 查询返回空结果，需要判断是“确实不存在”还是“数据未准备好”。
- 在技术设计中记录使用的 KG release。
- MCP 连接异常

## 2. `kg_resolve_entities`

### Tool 描述

> 将自然语言描述、服务名、仓库名、接口路径或资源名称解析为 Ground Truth KG 中的标准实体，返回精确匹配和排序后的候选匹配。

它解决的是“先找到正确实体，再进行图查询”。

### Agent 何时使用

- 用户只给了一个模糊业务名称。
- PRD 中出现服务或系统名称，但没有标准 ID。
- 查询接口前不知道它属于哪个 Service。
- 准备执行 `kg_get_context` 或 `kg_traverse_graph`。

## 3. `kg_get_context`

### Tool 描述

> 获取指定实体的任务相关上下文，包括关联仓库、服务、入口点、上下游依赖、数据资源、部署信息、候选关系、证据和数据缺口。

默认情况下最重要的 Tool，相当于 Agent 的“一站式上下文包”。

### Agent 何时使用

- 开始分析一个 Service 或 Repo。
- PRD 暗示存在跨服务影响。
- 准备编写技术方案或任务拆分。
- 需要同时获得关系、证据、候选项和覆盖率。
- 不确定应该调用哪一种专门查询。

## 4. `kg_traverse_graph`

### Tool 描述

> 从一个或多个起始实体出发，沿白名单关系进行有界图遍历，返回满足方向、深度、类型和属性条件的路径与实体。

“受限但通用”的图遍历接口。

### Agent 何时使用

- 分析多跳服务调用链。
- 寻找某个服务的两跳上游。
- 查哪些 Service 通过 EntryPoint 间接连接。
- 从 DataAsset 反向寻找影响服务。
- `kg_get_context` 返回的一跳信息不足。

## 5. `kg_get_evidence`

### Tool 描述

> 根据 `fact_id`、实体或关系获取产生该事实的证据，包括来源系统、源码位置、观察时间、证据类型和原始摘要。

回答：“KG 为什么认为这件事是真的？”

### Agent 何时使用

- 准备把 KG 关系写进技术设计。
- canonical 与当前代码看起来冲突。
- 需要定位关系对应的源码位置。
- 判断关系是代码扫描、运行时还是人工证据。
- 需要验证数据是否过期。

## 6. `kg_query`

### Tool 描述

> 使用受控的声明式查询 DSL 对 Ground Truth KG 执行组合查询。适用于领域 Tool 无法覆盖的复杂筛选、关系组合、分组和路径查询。

它比 `kg_traverse_graph` 更灵活，但仍不暴露 Cypher。




| DSL                        | Cypher                 |
| -------------------------- | ---------------------- |
| 只提供业务需要的有限表达能力             | 完整图数据库查询语言             |
| Agent 不需要了解内部 Neo4j Schema | Agent 必须了解 Label、关系和属性 |
| 容易限制深度、关系、数量和权限            | 自由度高，也更容易产生高成本查询       |
| 后端可从 Neo4j 换成其他数据库         | 与图数据库实现耦合              |
| 可自动补充证据、覆盖率和候选信息           | 默认只返回图查询结果             |
