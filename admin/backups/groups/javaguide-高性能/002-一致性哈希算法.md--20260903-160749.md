# 一致性哈希算法

> 一致性哈希主要用于分布式缓存、分库分表、负载均衡等场景，核心目标是：**当节点增加或删除时，只让少量数据重新映射，而不是让几乎所有数据都失效。**

一致性哈希会把整个哈希空间组织成一个首尾相连的`“哈希环”`，例如范围可以理解为 `0 ~ 2^32-1`。首先对服务器节点做哈希，把各个节点映射到环上的不同位置；然后对请求的 Key，比如用户 ID、缓存 Key，也做相同的哈希映射到环上。<span style="background-color: #fff3cd">某个 Key 最终会分配给从它所在位置开始，**顺时针遇到的第一个服务器节点**</span>。

例如：
```text
        Node A
       /      \
   Key1        Node B
      \        /
        Node C
```

普通取模哈希通常是：
```text
hash(key) % N
```

一旦服务器数量 `N` 发生变化，大量 Key 的计算结果都会改变，<u style="text-decoration-color: #e63946">导致大量缓存失效</u>。而一致性哈希中，如果新增一个节点，只会影响这个新节点与它前一个节点之间的一小段 Key；删除节点时，也只需要把原本属于该节点的数据迁移到下一个节点，因此数据迁移量明显更小。

一致性哈希还有一个常见问题：如果服务器节点在哈希环上分布不均，可能导致`数据倾斜`。实际项目中通常会引入**虚拟节点**，让一台真实服务器对应多个哈希位置，从而让数据分布更加均匀。

所以面试中可以概括为：**一致性哈希通过哈希环减少节点扩缩容时的数据迁移范围，并通过虚拟节点改善负载不均问题，适合动态扩缩容的分布式系统。**
