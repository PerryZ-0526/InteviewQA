# 一致性哈希算法

> 一致性哈希主要用于分布式缓存、分库分表、负载均衡等场景，核心目标是：**当节点增加或删除时，只让少量数据重新映射，而不是让几乎所有数据都失效。**

一致性哈希会把整个哈希空间组织成一个首尾相连的`“哈希环”`，例如范围可以理解为 `0 ~ 2^32-1`。首先对服务器节点做哈希，把各个节点映射到环上的不同位置；然后对请求的 Key，比如用户 ID、缓存 Key，也做相同的哈希映射到环上。<span style="background-color: #fff3cd">某个 Key 最终会分配给从它所在位置开始，**顺时针遇到的第一个服务器节点**</span>。

例如：
```text
        Node A
       /      \
   Key1        Node B
      \        /
        Node C
```

普通取模哈希通常是：
```text
hash(key) % N
```

一旦服务器数量 `N` 发生变化，大量 Key 的计算结果都会改变，<u style="text-decoration-color: #e63946">导致大量缓存失效</u>。而一致性哈希中，如果新增一个节点，只会影响这个新节点与它前一个节点之间的一小段 Key；删除节点时，也只需要把原本属于该节点的数据迁移到下一个节点，因此数据迁移量明显更小。

一致性哈希还有一个常见问题：如果服务器节点在哈希环上分布不均，可能导致`数据倾斜`。实际项目中通常会引入**虚拟节点**，<u style="text-decoration-color: #e63946">让一台真实服务器对应多个哈希位置，从而让数据分布更加均匀</u>。

> 虚拟节点是为了解决一致性哈希中**真实节点分布不均导致的数据倾斜问题**。如果一台真实服务器在哈希环上只对应一个位置，那么节点数量较少时，不同节点之间负责的哈希区间可能差异很大，某些服务器会承担更多数据和请求。引入虚拟节点后，一台真实服务器会通过不同的虚拟节点名称或编号，多次进行哈希，从而映射到哈希环上的多个位置，例如 `ServerA#1`、`ServerA#2`、`ServerA#3` 都属于同一台真实服务器。这样每台服务器就能分散到哈希环的多个区域，Key 仍然按照顺时针找到最近虚拟节点，再由虚拟节点定位到对应真实服务器。随着虚拟节点数量增加，各真实节点负责的哈希区间会更加均匀，负载也更平衡。除此之外，节点扩容或下线时，受影响的数据会分散到多个小区间中，不会集中迁移到某一台服务器。因此可以概括为：**虚拟节点本质上是给一台真实服务器在哈希环上创建多个映射位置，用空间换均衡性，从而降低数据倾斜并提升扩缩容时的负载稳定性。**

所以面试中可以概括为：**一致性哈希通过哈希环<u style="text-decoration-color: #e63946">减少节点扩缩容时的数据迁移范围</u>，并通过虚拟节点改善负载不均问题，适合动态扩缩容的分布式系统。**
