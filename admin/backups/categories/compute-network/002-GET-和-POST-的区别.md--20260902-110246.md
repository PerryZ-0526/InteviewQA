## 面试直接答

> GET 和 POST 最核心的区别不在“参数放哪里”，而在于 HTTP 语义：GET 用于获取资源，强调安全、幂等和可缓存；POST 用于提交数据并触发处理，通常可能改变服务器状态。

### 从协议语义上看

GET 表示`“获取指定资源”`，理论上不应该因为一次请求而修改服务器中的业务数据，因此 GET 被认为是“安全方法”。

这里的“安全方法”很容易误解，它不是说 **GET 比较安全、不会泄露数据**，而是 HTTP 里的一个专门术语。

> 所谓 GET 是“安全方法”，意思是：**客户端发起 GET 请求的目的应该只是读取数据，而不是修改服务器上的业务状态。**

同时，GET 具有`幂等性`，也就是说，同一个 GET 请求执行一次和执行多次，对服务器资源状态产生的影响应该相同。

POST 则表示`“把数据提交给服务器处理”`，常见于新增数据、提交表单、发起订单等场景，它可能导致服务器状态发生变化，因此通常不是幂等的。比如连续发送两次“创建订单”的 POST 请求，就可能创建两个订单。

### 在参数传递方式上

实际开发中 GET 的参数通常放在 `URL 的 Query String` 中，例如 `/user?id=1`；POST 的参数通常放在`请求体 Body` 中，可以使用 JSON、表单、XML、文件流等多种格式。

> 但这里要注意，这并不是 HTTP 协议对 GET 和 POST 的本质区分。<u style="text-decoration-color: #e63946">GET 理论上也可以带请求体，只是很多浏览器、服务器和中间件并不推荐或支持这种使用方式</u>；POST 也完全可以在 URL 中携带 Query 参数。

### 在缓存和浏览器行为方面

GET 天然更适合查询，因此浏览器、CDN、代理服务器<u style="text-decoration-color: #e63946">通常可以根据响应头对 GET 请求进行缓存，重复请求时可能直接使用缓存结果</u>。POST 默认一般不会被缓存，但 HTTP 协议并没有规定 POST 绝对不能缓存，只要响应头满足相应条件，技术上同样可以缓存。此外，GET 请求的 URL 可以被收藏、分享，也会进入浏览器历史记录；POST 的请求体不会直接体现在地址栏中，所以一般不能通过简单复制 URL 来完整复现请求。

### 很多面试中还会问到安全性。常见说法是“POST 比 GET 安全”，这个说法并不严谨

GET 参数出现在 URL 中，更容易被浏览器历史、服务器日志、代理日志记录，因此不适合直接放密码、Token 等敏感信息；但 POST 的请求体也不是加密的。如果使用 HTTP，GET 和 POST 都可能被窃听，<u style="text-decoration-color: #e63946">真正保证传输安全的是 HTTPS，而不是 POST 本身</u>。

### 另外，GET 参数受 URL 长度影响

HTTP 协议本身并没有统一规定 URL 最大长度，但<u style="text-decoration-color: #e63946">浏览器、Web Server、网关等组件通常会设置限制</u>，因此大量数据不适合通过 GET 传输。POST 数据放在请求体中，通常更适合提交大数据或上传文件，不过请求体大小同样可能受到服务器配置限制。

所以实际设计接口时，可以简单理解为：<span style="background-color: #fff3cd">查询资源优先使用 GET</span>，例如查询用户详情、商品列表；<span style="background-color: #fff3cd">需要创建资源或执行可能产生副作用的操作时使用 POST</span>，例如注册用户、提交订单。面试中如果只回答“GET 参数在 URL，POST 参数在 Body”，通常是不够的，更关键的是说明它们在 HTTP 语义、幂等性、安全性、缓存以及使用场景上的区别。
