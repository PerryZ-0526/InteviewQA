## 高频面试题

> HR 面通常不再深挖技术，核心是在判断四件事：你为什么来、你能不能稳定实习、你和岗位是否匹配、你这个人有没有风险。对于你这种已经过了前面业务面的候选人，HR 面更像是“动机 + 稳定性 + 综合素质 + offer 风险”的核验。

常见问题基本集中在下面这些。

1. 请简单介绍一下自己。

> 不要重复技术面那种项目细节。控制在 1 分钟左右，重点说：学校/方向 → 主要项目或实习 → 为什么投这个岗位。

你可以按照：
“我是计算机专业硕士，目前主要做 AI Agent 和后端相关的项目开发，之前做过教育智能体、邮箱智能助手等项目，技术栈主要是 Python、LangGraph、Redis、MySQL、Kafka 等。相比单纯做模型算法，我更喜欢把模型能力落到真实系统里，所以现在求职方向主要是 AI 应用、Agent 和 AI Platform 后端。这次岗位本身也涉及 Agent 和推荐场景，和我之前的项目经历以及后续的发展方向比较契合。”

> 面试官您好，我叫赵培源，本科就读于吉林大学计算机专业，专业课排名10%左右，保研到同济大学的计算机专业
>
> 获得到奖项有，本科的校级优秀毕设、国家励志奖学金、蓝桥杯省赛一等奖等
>
> 主要的项目经历是同济大学国豪书院立项的教辅智能体，为学生从入学到升学、就业的全生命周期的成长支持；相关技术掌握也很契合岗位要求；
>
> 也是有一段



2. 为什么投我们公司？

不要回答“平台大、发展好”。

最好回答三个层次：

第一，业务有吸引力。
第二，岗位和自己的经历匹配。
第三，自己未来也想继续这个方向。

例如：
“我比较看重的是这个岗位并不是单纯调用大模型，而是需要把 Agent 真正接到推荐业务里，涉及工具调用、上下文管理、工作流编排以及线上工程问题。这和我之前做 Agent 系统时积累的经验比较匹配。另外推荐本身也是一个数据和工程体系都非常成熟的业务，我希望了解 Agent 能不能真正进入成熟推荐系统，而不是只做 Demo。”



3. 为什么选择这个岗位？

HR 很可能会区分：

“你到底想做 Agent，还是后端，还是算法？”

建议不要给自己定义成纯算法。

可以回答：
“我的定位更偏 AI 应用/Agent 后端。我对模型本身有一定理解，但相比训练基础模型，我更擅长的是把模型、工具、数据和业务系统组织起来，解决上下文管理、任务编排、状态持久化、异步任务、成本和稳定性这些问题。所以这个岗位和我的能力结构比较匹配。”

4. 为什么不继续做你的研究方向？

这个问题对你比较容易出现，因为你的硕士研究方向和 Agent 并不完全一致。

不要说“科研没意思”。

可以说：
“研究生课题主要让我训练了算法建模和工程实验能力，但在做项目和实习过程中，我发现自己更喜欢偏系统和产品落地的问题。比如一个 Agent 真正上线以后，除了模型效果，还要考虑状态管理、工具调用、数据存储、延迟、成本和稳定性，这种问题对我的吸引力更强。所以就业上我会更倾向 AI 应用和后端方向。”

5. 为什么想来实习？

核心是不要表现成“为了简历”。

可以回答：
“我现在已经有一些完整 Agent 项目的开发经验，但目前更多是在项目层面。我希望进入真实的大规模业务环境，看看 Agent 在生产环境里是怎么和推荐系统、数据平台以及后端基础设施结合的，包括稳定性、成本和效果评估。这些是个人项目很难完整接触到的。”

6. 你对我们业务了解多少？

这是 HR 面里非常容易被低估的一题。

你之前已经知道部门主要做推荐，并且正在尝试 Agent + 推荐，那么就围绕这个回答。

例如：
“我目前了解到团队主体业务和推荐相关，同时也在尝试把 Agent 用到推荐场景里。但具体落地在哪些环节，我目前了解得还不算特别深入。所以前面面试的时候，我其实也比较关注目前已经落地或者正在探索哪些推荐 Agent 场景。”

这里不用装得什么都知道。

7. 为什么从上一段实习离职？

永远不要吐槽前公司、导师或者同事。

回答逻辑：
“实习阶段目标完成 + 希望接触更复杂业务。”

例如：
“上一段实习主要负责的是一个相对独立的 AI 应用项目，我把从需求、架构到实现的完整流程走了一遍。之后我希望接触更成熟、更大规模的 AI 系统，所以开始寻找 AI Platform、Agent 或推荐相关的机会。”

8. 你最大的优点是什么？

不要说“认真负责”。

最好说和岗位有关、并且有证据的。

你比较适合的答案是：

“我一个比较明显的特点是工程完整性比较强。我做 Agent 项目时不会只停留在 Prompt 或模型效果，而会继续考虑状态怎么持久化、失败怎么恢复、Redis/MySQL 怎么分工、工具调用怎么审计、LLM 成本怎么控制。这个习惯让我比较适合做偏生产系统的 Agent 开发。”

9. 你的缺点是什么？

HR 最经典的问题。

不要说：
“我太追求完美。”
“我工作太认真。”

这种已经烂大街。

你可以说一个真实但可控的问题：

“我之前做项目的时候容易在架构设计阶段花比较多时间，会希望把边界和模块设计得比较完整。但后来我发现早期项目更重要的是先验证核心链路，所以现在会先做最小可运行版本，再根据实际问题逐步增加复杂度。”

这个回答对你的项目经历也比较一致。

10. 你遇到过最大的困难是什么？

HR 不关心技术细节本身，而是看：
怎么发现问题 → 怎么解决 → 有没有复盘。

最好选你 Agent 项目中的一个真实问题，比如架构过度设计、RAG 延迟、LLM 调用成本或者状态管理。

回答尽量使用：

“最开始……”
“后来发现……”
“我做了……”
“最后……”
“这件事让我意识到……”

11. 有没有和别人意见不一致的时候？

HR 在测协作能力。

不要回答“没有”。

可以回答：
“有。一般技术方案分歧我不会一开始就争哪一种更先进，而是先把评价标准确定下来，比如开发成本、延迟、稳定性和后续扩展性。如果两种方案都合理，就会用最小实验验证。因为很多架构争议其实不是对错问题，而是不同约束下的取舍。”

12. 如果 Leader 给你的方案你不同意怎么办？

标准逻辑：

先理解背景 → 给出依据 → 提方案 → 最终服从团队决策。

可以说：
“我会先确认自己是不是缺少一些业务背景。如果确实存在风险，我会把问题和依据明确提出来，同时给出替代方案，而不是单纯说这个方案不好。如果讨论以后仍然决定采用原方案，我会按照团队决策执行，并在实现过程中把风险监控好。”

13. 如果任务很多，你怎么安排优先级？

建议回答：

业务影响 &gt; 截止时间 &gt; 前置依赖 &gt; 实现成本。

比如：
“我一般先区分阻塞型任务和非阻塞型任务。会优先处理影响其他人、影响上线节点或者有明确 deadline 的任务。对于复杂任务会拆成若干可以交付的小阶段，避免一直做到最后才发现方向有问题。”

14. 能接受加班吗？

不要回答“完全接受”，也不要直接说“不接受”。

比较正常的是：
“如果是上线节点、紧急故障或者阶段性项目压力，我可以接受必要的加班。我更关注的是团队是不是有比较合理的目标和优先级管理，而不是长期依赖无效加班。”

对于实习招聘，通常更推荐稍微保守一点：
“阶段性的加班没有问题。”

15. 实习多久？什么时候可以入职？每周几天？

这几个问题非常重要，有时候比技术问题还重要。

HR 会判断稳定性。

一定要给明确答案，不要说：
“看学校安排。”
“应该可以。”
“差不多。”

尽量说成：
“最快 X 月 X 日可以开始，每周可以保证 5 天，至少连续实习 X 个月。”

HR 非常喜欢确定性。

16. 学校那边会不会有事情影响实习？

会问：
课程、毕业论文、导师、答辩、实验。

你需要表现出已经规划过。

例如：
“目前课程压力已经比较小，研究生课题也有明确安排。我会提前和导师协调，不会频繁因为学校事务影响正常实习。如果有必须参加的学校事项，也会提前沟通。”

17. 你现在还有哪些公司的流程？

一定如实说，但不要详细报菜名。

可以说：
“目前还有几家 AI 应用/后端相关岗位在流程中，不过阶段不完全一样。这边的岗位和我的方向匹配度比较高，所以我会比较认真考虑。”

如果已经有 offer：
“目前确实有一个 offer，但我还没有最终决定，我会综合看岗位内容、团队方向和成长空间。”

18. 如果我们给你 offer，你会来吗？

这个问题实际上在判断 offer 接受率。

如果你确实意愿比较高：

“目前从业务方向、岗位内容和前面几轮面试的沟通来看，我对这个岗位意愿比较高。如果薪资、入职时间这些基本条件没有明显冲突，我会优先考虑。”

不要轻易说：
“100% 会来。”
除非真的如此。

19. 你选择 offer 最看重什么？

推荐排序：

业务内容 &gt; 团队/mentor &gt; 成长 &gt; 公司平台 &gt; 薪资。

比较好的回答：
“我目前还是职业早期，所以首先看具体做什么以及能不能真正参与核心业务，其次是团队和 mentor 能不能让我形成比较完整的工程能力。在这些差异不大的情况下，才会进一步考虑薪资和其他因素。”

20. 未来 3～5 年的职业规划是什么？

不要说：
“成为架构师。”
“成为技术专家。”

太虚。

你可以说：
“短期我希望先把 AI 应用和后端基础打扎实，不只是会调用模型，而是真正能够负责一个 Agent 系统从设计、开发到上线。之后希望逐步积累大规模 AI 系统的经验，包括模型服务、数据、评估、成本和稳定性。至于更长期，我希望成为能够独立负责 AI 应用或 Agent 平台核心模块的工程师。”

21. 为什么不考虑算法岗？

如果被问到，可以直接：

“我并不是排斥算法，而是相比单纯模型训练，我更喜欢模型和工程系统之间这一层。我比较有兴趣的是怎样让模型可靠地使用工具、管理状态、处理长上下文、和真实业务系统交互，这类问题更接近 AI 应用和平台工程。”

22. 你觉得自己为什么适合这个岗位？

这是很重要的总结题。

你可以浓缩成三点，但口头回答不用真的编号：

“第一，我已经实际做过多个 Agent 系统，而不是只了解概念；第二，我的项目不仅涉及 LLM，还涉及 Redis、MySQL、Kafka、RAG、状态管理这些后端问题；第三，我自己对 Agent 系统工程化的问题比较感兴趣，包括记忆、上下文、工具调用、成本和可靠性。所以我觉得自己的经历和岗位要求匹配度比较高。”

23. 你期望的实习薪资是多少？

如果 HR 没给范围，尽量不要主动报死数字。

可以回答：
“我目前更看重岗位内容和团队，如果公司对于这个岗位有统一的实习生薪资标准，我可以按照公司的标准来。”

如果对方一定让你报：
“我了解同类岗位大概是 X～X，我的预期也在这个范围，具体可以根据公司的职级和标准来。”

24. 你还有什么想问我的？

HR 面最后一定要准备问题。

不建议继续问特别深的 Agent 技术架构，因为 HR 很可能不知道。

适合 HR 的问题是：

“这个岗位后续的流程和时间节点大概是怎样的？”

“实习生进入团队以后，一般是独立负责一个模块，还是参与现有项目？”

“这个岗位对于实习周期有没有比较明确的要求？”

如果前面业务面已经聊得很充分，也完全可以只问流程。

对于你这次面试，我认为最需要提前准备好的不是 24 个问题，而是 8 个核心答案：自我介绍、为什么这家公司、为什么这个岗位、为什么做 Agent/AI 后端、为什么和硕士研究方向不同、最大的优缺点、职业规划、其他 offer/是否会来。

HR 的大量追问，本质上都是围绕这 8 个答案交叉验证。最重要的是前后一致，不要为了每一道题分别编一个“标准答案”。
